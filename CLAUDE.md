# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

This is a matching decompilation project for **KKND: Krush Kill 'n Destroy** (MS-DOS, 1997,
Beam Software). The goal is C code that, when compiled with a Watcom C 32-bit compiler, produces
exactly the same machine code as the retail executable, and a rebuilt `KKND.EXE` that is
byte-identical to the original.

**Target:** `dumps/disc/KKND/KKND.EXE` (SHA-1 `024e96860c504b462b24b9237d49bfe8de6eb8e0`),
a Watcom C program bound to DOS/4GW Professional (Linear Executable).

**Status:** Phase 0 done (split + byte-identical rebuild + per-function verification), first
functions matched. See `PLAN.md` for the roadmap and `PROGRESS.md` for the count.

## Project Structure

- `src/<module>.c` decompiled C, one file per original module (names from the exe's own
  `__FILE__` strings: `main.c`, `units.c`, `mission.c`, …); `src/lib/` = linked libraries
- `include/` headers (`common.h` has the basic types and `INCLUDE_ASM`)
- `asm/DOS/nonmatchings/<func>.s` per-function disassembly (generated by `tools/split.py`, gitignored)
- `configs/DOS/functions.csv` every function (VA, size, span); `units.csv` module ranges;
  `symbols.txt` real names (`name = 0xVA;`); `cflags.txt` compiler flags; `KKND.EXE.sha1`
- `dumps/` your own game files (gitignored); `build/` outputs (gitignored)
- `tools/` the toolchain (below)

## Tools

- `python tools/build_kknd.py` — **the gate.** Compiles `src/**/*.c`, verifies every C function
  against the original (bytes + relocation targets), splices, rewrites the LE, checks SHA-1.
  Success = `build/DOS/KKND.EXE: OK`. `-v` prints instruction diffs for failures.
- `python tools/match.py <file.c> [--func NAME] [--flags "..."]` — per-function matching loop
  with a side-by-side diff (ours | target). Use a scratch file, iterate, then land.
- `python tools/score_functions.py [--unit units.c] [-n 40]` — rank the easiest unmatched functions.
- `python tools/split.py` — regenerate `asm/DOS/nonmatchings/` (after renames in `symbols.txt`).
- `python tools/find_functions.py` — re-run function discovery (rewrites `functions.csv`; only
  when discovery itself is improved — function names/VAs are the project's keys).
- `python tools/gen_units.py` — rebuild `configs/DOS/units.csv` (never overwrites `src/`).
- `python tools/le.py` / `python tools/omf.py <obj>` — dump the LE / an OMF object.
- `python tools/learn.py <terms>` — search `DECOMPILATION_LEARNINGS.md` by section.
  `CODEGEN_MODEL.md` is the short model of Watcom codegen those entries instantiate — read it first.
- `python tools/make_report.py` — decomp.dev (objdiff v2) report; `update_readme_progress.py --sync`.

Toolchain: the patched Open Watcom `wcc386` (`doc/compiler_patch.md`; `$WATCOM`, else
`tools/watcom/`, else `D:/programs/re/openwatcom/patched`, else stock OW 1.9). `wcc386` splits paths on spaces and reads `/` as an option switch, so the
tools always compile from `build/tmp` with relative paths — keep it that way.

## Toolchain / compiler

Watcom C/C++32 (runtime banner "1988-1994", i.e. Watcom 10.0/10.0a class). Flags pinned in
`configs/DOS/cflags.txt`: `-s -of+ -5r -omilert -zm -zp1`. Calling convention = Watcom register:
args in EAX, EDX, EBX, ECX then stack; callee saves every register it uses except EAX;
functions get a trailing `_` (`func_00012080_`), data a leading `_`. See `COMPILER_ANALYSIS.md`.
A file can override flags with a first line `/* cflags: ... */`.

## Code Quality Standards

### Struct Usage

**NEVER use pointer arithmetic with manual offsets.** Always define and use proper structs.

**BAD:**
```c
int func(void *arg0, int arg1) {
    return *(short *)((char *)*(void **)((char *)arg0 + 0xC) + arg1 * 36 + 0xA);
}
```

**GOOD:**
```c
typedef struct {
    s16 unk0;
    u8 _pad[0x8];
    s16 unkA;
    u8 _pad2[0x18];
} ArrayElement; /* size 0x24 */

typedef struct {
    u8 _pad[0xC];
    ArrayElement *unkC;
} FunctionArg;

int func(FunctionArg *arg0, int arg1) {
    return arg0->unkC[arg1].unkA;
}
```

When you see `[reg + offset]` patterns: identify offset / element size / field, define the
element and container structs (real names or `field_XX`), verify the struct size matches the
multiplier, then write `->` / `.` accesses. Types go in the owning module's header.

### When Decompiling

If you write code with pointer arithmetic: **STOP**, create the struct first.

## Tasks

### Decompile assembly to C code

1. `python tools/score_functions.py` → pick a function; read `asm/DOS/nonmatchings/<func>.s`.
2. Write attempts in fresh scratch files; `python tools/match.py scratch.c --func <func>`.
   It's okay to give up after ~10 real attempts.
3. Replace the `INCLUDE_ASM(...)` in `src/<module>.c` with the matching C. Declare callees with
   their real signatures (call sites teach the types: EAX/EDX/EBX/ECX usage before a `call`).
4. Data a function touches must be an `extern` symbol (`D_000B98D8` or a real name in
   `symbols.txt`), never a literal address; string literals likewise (the build refuses local
   segment references until string/data placement is modelled).

**Post-success (always):**
1. Delete scratch files.
2. Record generalizable findings in `DECOMPILATION_LEARNINGS.md` (new Watcom codegen quirk,
   matching trick, struct/layout insight). Short problem → symptom → fix, minimal example.
   This is the project journal — it grows with every match. Engine/format facts go in
   `KKND_NOTES.md` instead.
3. Include the learnings edit in the match commit (or a follow-up).

### Verification Requirements

1. **NEVER declare success on `match.py` alone.** A scratch match does not prove the build.
2. **ALWAYS** run `python tools/build_kknd.py`.
3. **SUCCESS CRITERIA:** `build/DOS/KKND.EXE: OK`. Anything else = not done.
4. On struct changes: rebuild; every function using that struct must still match.

### Commits

One matched function = one commit, message `matched <function> <attempts>`. A function that
floors out after real effort goes in `tools/difficult_functions` as
`<function> <attempts> <best bytes differing>` — and revert the partial C (no incomplete matches).
Run `python tools/update_readme_progress.py --sync` and commit README + PROGRESS with the match.

## Self-Review Checklist

- [ ] No pointer arithmetic with manual offset calculations
- [ ] All struct field accesses use `->` or `.`
- [ ] No `void *` params that should be typed structs
- [ ] Struct sizes match the assembly access patterns
- [ ] New types/APIs live in the correct module header
- [ ] `python tools/build_kknd.py` prints `build/DOS/KKND.EXE: OK`

## Assets / licensing

**Never commit game data.** `dumps/ asm/ build/` are regenerated from the user's own CD and are
gitignored. `configs/DOS/functions.csv` (addresses and sizes only) is committed because the
decomp.dev report is computed from it in CI. Only program *structure* (dispatch tables, short
strings a matched function needs) belongs in C.
